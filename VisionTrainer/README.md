# VisionTrainer：原点四步控制台

2026-10-26 新增本地控制台。双击项目根目录的 `启动姿态控制台.cmd`，或运行本目录的 `launch_console.ps1`。启动器使用已有 `.venv-gpu`，在 `http://127.0.0.1:18763` 打开页面；已有同版本服务运行时直接打开，不重复启动。

2026-10-26 初次交付仅包含功能代码和启动入口；该历史交付当时未做板端验收。当前模型切换机制已与应用运行时更新分开，具体模型及当前组合验证以部署记录和本次板端证据为准；模型成功加载不代表识别准确率、计数或 GPIO 已验收。

## 四步使用

1. **画面与范围**：读取HDMI原始截图，拖框或输入1080p坐标；默认中央512×288。可调曝光、模拟增益、数字增益、对比度、亮度、白平衡R/B和直方图。修改参数后自动保存并实读，数值输入合并450毫秒内的连续修改，开关立即进入队列；每笔实际完成后才提交下一笔，仅提交编辑字段。手动调节某项数值会关闭该项自动调节。白平衡没有自动/手动模式选择：自动校准与人工输入都修改同一组R/B，始终可见、可编辑、可固定。“自动调整”读取已有未压缩原生快照的灰白参考统计，最多6次评估、每次R/B最多变化24，使用既有接口保存并回读；参考不足时保留R/B数值并提示，偏差未收敛时提示人工检查。之后启用板端既有五项自动调光，持续更新对应输入参数。自动曝光保留一次有界调节入口。“固定参数，进入采集”先等待保存完成，再暂停自动调光、比较暂停前后的实际参数并取得原生选区试拍；不切换白平衡或重写成像参数。旧页面开启的FPGA隐藏自动白平衡不会在读取页面时被擅自更改，需由用户点击自动调整或编辑R/B后同步为可见参数。
2. **采集与打标**：现拍15张，可补齐不足张数、排除并保留坏图。明确选择独立画框模型后点击自动画框，或者先手工完整确认3张图再从零训练新助手。拖动画框、移动框、角点改大小、数字坐标编辑、撤销、删除、A/B/C等姿态指定、草稿保存和逐图确认均有真实后端处理。旧助手仅使用定位分支，跳过会缩放图像的复核器；候选框需要人工确认。
3. **训练与测试**：随机初始化、CUDA训练，复用原有网络与训练损失，禁用所有图像增广与缩放。按整张源图划分开发验证集，再生成512×288原生裁剪窗口。训练后通过已有WSL工具链转换RKNN；转换失败保留GPU模型，可单独重新转换。明确选择训练时间后现拍10张同规格新图并GPU推理。失败图可以转纠错，人工修改后加入下一轮随机初始化训练；该测试组随即退出独立验收。
4. **上板与控制**：查看实际训练北京时间、场景、批次和SHA256，并明确选择后才切换模型。模型切换只上传 `detector_fp16.rknn` 和模型 `config.json` 的训练原件，另签发模型授权元数据；不上传运行源码、不修改服务入口、不覆盖现场配置。ROI位置、置信度和姿态确认次数通过独立的热更新操作控制；推理ROI宽高锁定为当前模型输入尺寸（本次512×288）。网页直接显示HDMI截图，不在PC重新推理或重画板端结果。

## 图像与硬件边界

- 数据使用原生RGB，网页使用未压缩BMP；不生成缩略训练图、不拉伸、不降采样、不做有损压缩。浏览器的等比适配只影响显示。标注与预测框是独立数据，不写入训练原图。
- Web控制台每张原生RGB采集图的选区面积上限为518,400像素（宽×高，含边界），试拍、15张训练采集、补采与10张新图测试共用此限制。页面在发送请求前检查，后端在创建任务前检查，板端采集事务发送前使用同一矩形校验；旧流程的超限选区也会被拒绝，须回第一步缩小并重新冻结。不会自动缩放原图或改写历史图像，完整HDMI预览不受此采集上限限制。
- 当前网络输入为512×288，训练采集区至少512×288，更大训练图仅切分为原生窗口。第四步推理ROI宽高必须等于当前模型输入，位置可调，不补像素、不缩放；模型切换不能自动改写ROI以适配另一种输入尺寸，尺寸冲突在停服务前明确拒绝。
- 板端窗口网格固定在1080p坐标系，合法区改变不会改变元件长宽比或像素大小。大范围增加模型调用量，实际推理速度等待用户实测。
- HDMI截图包含板端已有的显示缩放，这是显示结果；截图不用于训练。截图源帧号来自相邻遥测，不声称截图与该源帧号原子同步。X11截图需要板端 `xwd`、`xrandr` 与现有X会话。
- 模型部署根据实际 `/proc` 入口与其模块搜索路径记录运行版本，不能把工作目录中的旧源码当成运行版本。计划中的白名单外文件、入口变化、运行模块变化、非模型环境或现场配置变化均在停服务前阻断，并列出具体差异；提交后再次核对模块和现场配置哈希。应用运行时兼容更新须独立执行，不能借模型部署替换UI、图表、预览、调度、跟踪或采证程序。
- 板端模型切换会短暂重启视觉服务。连续运行的60 FPS须另行验收；页面分别显示各显示端去重源帧率、重绘率与模型调用率，缺失遥测显示为空，不以历史值代替。

## 多页面与任务

- 新流程独立保存，旧页面、旧任务记录或浏览器缓存不禁止新建。每个页面有自己的操作身份；同一流程的最新主动任务可取消旧任务。
- GPU与板卡分别串行仲裁，最近的主动操作优先；后台读取和轮询不抢控制权。旧的等待任务被取消，不在新操作完成后自行恢复运行。
- 已提交板端事务必须收尾后释放资源，不覆盖正在执行的采集。结果已存在的旧标记会保留归档；配置已过期且尚未执行的请求可归档。真实硬件忙碌有等待时限和明确错误，不无限卡住页面。
- 模型切换提交阶段短暂不可中断；避免半切换。任务取消保留已经写出的原图、标注和训练产物。
- 标注保存以当前主动提交的页面为准，上一版本保留在标注历史里。自动候选生成不会覆盖其间人工修改的图。
- 不自动采用浏览器保存的模型选择；每次测试与部署都需要页面上的明确动作。部署选择有一次性令牌和10分钟期限。

## 文件位置

- `console_app.py`：本机HTTP入口、同源/会话校验、图片与模型下载。
- `console_web/`：四步HTML、CSS、JavaScript；无需Node构建或前端依赖下载。
- `console_store.py`、`console_workflow.py`、`console_jobs.py`：流程、版本、任务和资源调度。
- `console_board.py`：SSH/SFTP事务、相机控制、未压缩HDMI截图。
- `console_worker.py`：独立CUDA画框、训练和测试进程。
- `console_model_deploy.py`、`console_runtime_probe.py`：模型专用白名单切换与实际入口/模块/现场配置的只读来源核对。
- `model_input_adapter.py`：原运行程序中的模型输入输出兼容层；安装或更新属于独立的运行时操作。`console_runtime.py` 中的历史源码适配工具不被模型切换调用。
- `console_data/<流程ID>/`：新流程原图、标注历史、训练版本、测试组与部署记录。
- `console_logs/`：服务和任务日志；`console_jobs/`：任务完成记录。历史任务状态不会恢复成占用锁。
- `console_settings.json`：新控制台配置。旧 `settings.json` 仅作初始连接参数来源。
